The big picture

You give one instruction. Claude reads the workflow file to know the steps, reads the brand file to know the look, and runs small Python tools that do the actual work. Only three things leave your computer: web research, the image API and Gmail.

Phase A · once per project

Build the pipeline

Six prompts, in this order. Start the first one in plan mode (Shift+Tab) so Claude proposes before it builds.

  1. Plan the stack

    Claude asks a few questions (delivery, infographic style, research method, trigger) and writes a plan you approve.

    Prompt 
    I want to build a newsletter automation workflow. I tell you "newsletter about <topic>" and you research it, structure it as HTML, make it look good, and create a few infographics to go with it. Help me pick the tech stack, and suggest what I haven't thought of yet.

  2. Build the tools

    This gives you the five scripts in tools/, a Jinja2 email template, config/brand.json and workflows/newsletter.md.

    Prompt 
    Approved. Build it: Jinja2 + premailer for Gmail-safe HTML, matplotlib charts, images as CID attachments, a QA script (102KB clip limit, alt text, every stat needs a source), and Gmail drafts by default. Test it end to end on a sample issue with placeholder data and screenshot it at desktop and mobile width.

  3. Apply your brand

    Attach the brand sheet with @. Claude reads the colours, type and rules, crops the logo pixel-for-pixel, and adds a QA check that fails on banned colours.

    Prompt 
    Make sure the whole newsletter is branded based on @brand_assets/<Brand-Sheet>.png and the logo @brand_assets/<logo>.png. Follow every do/don't rule on the sheet, use the brand fonts in the charts too, and make the QA check fail on off-brand colours.

  4. Connect hero images

    Put the key in .env yourself. Don't paste it into the chat.

    # .env KIE_API_KEY=your-key-here
    Prompt 
    KIE_API_KEY is in .env. Build tools/kie_image.py for hero images (Nano Banana 2, 16:9). Append the brand image style to every prompt automatically: flat, brand palette only, no text. Add --balance and --dry-run so I can check costs, then generate one test hero.

  5. Connect Gmail

    Pick a login method using the Gmail login guide below, then:

    Prompt 
    Gmail login is set up (app password in .env / credentials.json in the root). Create a draft of the sample issue. If OAuth needs consent, run it with python -u in the background and give me the sign-in link.

  6. Lock in what you learned

    The workflow file is Claude's instruction sheet for every future issue, so keep it current.

    Prompt 
    Update workflows/newsletter.md with everything we learned: setup steps, the content.json schema, brand rules, costs, and every error we hit and how we fixed it.
Phase B · every issue

Make an issue

One prompt starts all seven stages. Each stage leaves a file in .tmp/<date>-<topic>/, so you can see and change any step.

Prompt · basic 
Write a new newsletter about <topic>.
Prompt · with a brief 
Write a new newsletter about <topic>.
Audience: <who>. Angle: <beginner explainer / latest news / contrarian take>.
Length: ~<900> words, <4> sections, 2–3 charts.
Only use primary sources (filings, peer-reviewed studies, official announcements). Tell me what you rejected and why.
Follow-up promptWhat happens
"Show me the preview"Opens preview.html in your browser
"Make section 2 shorter and punchier"Edits content.json, then re-renders and re-checks
"Regenerate the hero: <new idea>"New kie.ai image (~8 credits)
"Highlight <X> in the chart"Moves the single accent colour to that bar, slice or point
"Give me 3 more subject lines"Options of 50 characters or less, added to subject_alternatives
"Send the draft to <email>"Runs gmail_send.py --send --to …. It only sends when you ask.
Under the hood

How the email is built

Gmail removes most CSS and blocks embedded data: images. So the CSS is written inline on every element, and the images travel as attachments that the HTML points to with cid: links.

Phase A · step 5

Which Gmail login?

Creating drafts or sending needs your permission on the account. A plain API key can't give that.

✓ Easiest

App password

  • Turn on 2-Step Verification
  • Create one at myaccount.google.com/apppasswords
  • Add GMAIL_ADDRESS and GMAIL_APP_PASSWORD to .env

Drafts go in over IMAP, sending goes out over SMTP.

✓ Works

OAuth client

  • Google Cloud: enable the Gmail API
  • Consent screen → External, then add yourself as a test user
  • Clients → Desktop app → save as credentials.json
  • First run: approve once in the browser
✕ Won't work

API key (AIza…)

  • Only reaches public data
  • Can't create drafts or send
  • If you pasted one somewhere, restrict or delete it
Phase C · new project

Reuse it anywhere

The pipeline doesn't depend on any one brand. Copy these files, swap the brand, run the sample.

your-new-project/
├── CLAUDE.md                # WAT rules (copy as-is)
├── requirements.txt         # jinja2 premailer matplotlib requests python-dotenv google-*
├── .env                     # KIE_API_KEY, GMAIL_* (never commit)
├── config/brand.json        # ← the only file that changes per brand
├── templates/newsletter.html.j2
├── tools/
│   ├── make_charts.py   render_newsletter.py
│   ├── check_newsletter.py   kie_image.py   gmail_send.py
├── workflows/newsletter.md
├── docs/newsletter-cheatsheet.html   # this page
└── brand_assets/            # sheet, cropped logo, font .ttf files

  1. Copy and install

    cp -r old/{CLAUDE.md,requirements.txt,config,templates,tools,workflows,docs} new/ cd new && python -m venv .venv && .venv/bin/pip install -r requirements.txt

  2. Re-brand with one prompt

    Prompt 
    Read workflows/newsletter.md. Re-brand this pipeline for @brand_assets/<new-sheet>.png: rewrite config/brand.json (colours, fonts, voice, rules, image_style), crop the logo exactly, download the brand font for the charts, and adjust the template if the brand's components differ. Then run the sample issue and show me screenshots.

  3. Add keys and test

    Add the .env keys and the Gmail login (Phase A, steps 4–5), then ask for the first issue.

Commands and fields

Claude runs these for you. You'd only need them to debug by hand.

# D=.tmp/2026-10-13-my-topic .venv/bin/python tools/make_charts.py $D .venv/bin/python tools/kie_image.py --balance .venv/bin/python tools/kie_image.py --prompt "subject only" --out $D/img/hero.png .venv/bin/python tools/render_newsletter.py $D .venv/bin/python tools/check_newsletter.py $D # add --offline to skip link checks .venv/bin/python -u tools/gmail_send.py $D # draft; --send --to a@b.com to send
content.json fieldWhat it does
titleHeadline. Wrap one word in <em> to colour it in the accent.
stats[]Three stat cards: value, label, source, emoji
charts[]bar · hbar · line · donut · timeline. highlight marks one item. source can be a list.
sections[]eyebrow, heading, paragraphs, optional chart and callout
sources[]Numbered list. QA fails if a stat or chart cites a missing id.
ctaOverrides brand.json. Hidden while enabled: false or with no URL.
Learned the hard way

Gotchas

  • Never paste secrets into the chat. Edit .env or drop credentials.json into the folder yourself. If a key was pasted, rotate it.
  • A Google API key won't work for Gmail. Drafts need your consent: an app password or OAuth.
  • Gmail clips HTML over ~102KB and blocks data: images. Send images as CID attachments; a typical issue is 20–30KB.
  • Jinja autoescape breaks CSS. Mark style values | safe, or quoted font names become &#39; and the text falls back to serif.
  • premailer downloads <link> stylesheets. Add data-premailer="ignore" to the Google Fonts link.
  • Image models garble text. Put "no text, letters or numbers" in every image prompt. All data goes in code-drawn charts.
  • kie.ai can time out (524). Failed tasks aren't charged. Check --balance, then retry once.
  • Some sites block link checks (403). SEC, DOI/Wiley and investor sites block bots. A 403 there isn't a dead link.
  • Market-size reports disagree wildly. Prefer filings, peer-reviewed studies and official announcements, and keep the rejects in research.json.
  • The OAuth sign-in link can be hidden. Run gmail_send.py with python -u so the link prints straight away.
