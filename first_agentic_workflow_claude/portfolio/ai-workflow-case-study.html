The point

The value isn't that AI wrote a report. It's that the report can be trusted and re-run: the same structure, the same evidence rules and the same branded output every quarter, with a person approving each stage.

02 · The problem

Why "just ask the AI" doesn't work for research

Accuracy compounds

Small errors multiply

If each step is 90% accurate, five steps in a row succeed only 59% of the time. A long research task done in one go drifts.

Unsourced claims

Plausible isn't verified

Language models produce confident text. Without a hard rule, a report mixes facts, company self-claims and guesses.

One-off output

Nothing repeatable

A chat answer can't be re-run next quarter with the same structure, branding and quality bar.

The design answer

Split the work by what each part is good at. AI decides and writes — which competitors matter, what a page says, what the evidence means. Code executes — fetching sites, scoring speed, checking citations, merging data, drawing charts, laying out the PDF. A person approves at fixed checkpoints.

03 · Architecture

Three layers: Workflows, Agents, Tools

The project follows a "WAT" structure. Instructions live in plain-language SOPs, the AI agent orchestrates, and Python scripts do the deterministic work.

04 · The algorithm

End-to-end flow, with human checkpoints

The workflow runs in phases. Build phases happen once; run phases repeat every time the report is refreshed. Diamonds are checkpoints — the agent stops until the owner approves.

The same algorithm, as pseudocode

run_report(market, date):
    profile  ← read("business-profile.md")             # owner-confirmed facts
    brand    ← read("brand/brand.json")
    known    ← latest("research/source_check_*.md")    # verified facts + known-false claims

    list     ← agent.propose_competitors(profile, search)    # 5–8 direct, 2–3 indirect
    checkpoint A: owner approves list

    parallel for c in list:                               # one sub-agent each
        files[c] ← agent.research(c, brief, known[c])     # JSON matching the schema
    seo   ← tool.seo_snapshot(all_sites)
    speed ← tool.pagespeed(all_sites)

    report ← tool.merge(base, files, speed)           # dedupe + renumber sources
    repeat until tool.validate(report) = PASS:
        fix(report)                                   # drop or re-source failing claims
    checkpoint B: owner reviews findings

    report.analysis ← agent.analyse(report)           # matrix, gaps, recommendations
    checkpoint C: owner reviews analysis

    pdf ← tool.render(report, brand)                  # charts + template + WeasyPrint
    qa(pdf)                                           # fonts, page count, visual check
    checkpoint D: owner signs off
    update_sop(lessons_learned)

06 · Building trust into the output

The validation gate and the evidence rules

The single most important design decision: the PDF cannot be rendered unless a deterministic validator passes. The AI is told the rules; the code enforces them.

What the validator checks

  1. SchemaEvery field matches a JSON schema; every claim carries at least one source id.
  2. CitationsEvery cited id exists; every external source has a URL and an ISO access date.
  3. CompletenessThe comparison matrix scores every dimension for every company.
  4. No placeholdersProduction runs fail on "Sample" or "TODO" text and example URLs.
  5. Forbidden termsNames that must never appear in a report are blocked.
  6. Live links404s and dead domains fail; bot-blocked pages are flagged for a manual check.

Evidence rules every agent follows

FactOnly cite pages actually opened. A search snippet is marked as one.
ClaimCompany statements are labelled: "claims 60+ banks", not "serves".
InferenceReasoning is marked "likely" or "suggests" — never stated as fact.
GapNo evidence → "not publicly disclosed", citing where it was checked.

Old data is treated as unverified

Before research, the internal files (a previous study, sales decks) were checked against live sources by three parallel agents. About 50 claims were marked confirmed, outdated, contradicted or unverifiable. Examples of what that caught:

Outdated

A competitor's client count had changed (45+ banks → 60+ today).

Unsupported

A "80% market share" figure had no public source and was dropped.

New

Regulator notices revealed 71 licence cancellations, not the 63 on file.

08 · Stack

Tools and why they were chosen

LayerChoiceWhy
AgentClaude Code (plan mode, sub-agents)Plans before acting, asks questions in one batch, runs parallel research agents.
ResearchWeb search + page fetchFree; every claim points to a page that was actually opened.
Site datarequests + BeautifulSoup; Google PageSpeed APISame checks on every site, every run; free speed and SEO scores.
Data contractJSON SchemaAgents' output has one fixed shape, so code can merge and check it.
PDFJinja2 + WeasyPrint (HTML/CSS)Running headers, page numbers, clickable citations, brand fonts embedded.

Seven tools in total: brand extractor, SEO snapshot, PageSpeed, validator, merge, charts and renderer — about 1,250 lines of Python, plus a 265-line schema and a 120-line SOP.

Habits that made the difference

Plan before code

Plan mode plus "don't write code until I approve" kept the build in the right order.

Design before research

Approving a placeholder PDF first meant no research effort was wasted on a layout that would change.

Delegate a decision explicitly

"You take the decision" works — Claude then states the choice and its reason in one line.

Never paste secrets into chat

Put API keys straight into .env, and restrict each key to the one API it needs.

10 · Reuse

Adapting it to another market

Only three inputs change: business-profile.md, the files in brand/, and the market named in prompt 8. The schema, tools, validator, template and SOP are reused as they are. The same pattern — agent decides, code executes, human approves, validator gates — fits any research deliverable where trust matters: due diligence, supplier screening, grant landscapes or policy monitoring.
